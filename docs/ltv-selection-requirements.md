# LTV 选品链路需求
## 1. 背景与目标
现有选品链路基于已实现 ROI：短剧看阶段判定，素材看阶段 + A 方案三道闸门，campaign 看分段 ROI。该口径只能识别「已经赚到钱」的目标，无法利用用户级长期价值预估。
本期新增一条**并联**的 LTV 选品链路，引入用户级预测 LTV，覆盖素材、短剧、campaign 三个维度，输出 `FOLLOW_UP` 信号。
目标：在目标当期 ROI 未过线时，用预测长期价值提前识别值得新建投放的目标；与现有 ROI 链并行，不替代、不改动现有判定。
本期交付需求文档与前端原型（Dashboard / Decisions / Config），不涉及后端、API、诊断服务代码，也不涉及投放执行。
## 2. 范围与边界
| 项 | 范围 |
|---|---|
| 覆盖维度 | 素材、短剧、campaign |
| 输出信号 | 仅 `FOLLOW_UP`；是否产 `ELIMINATE` 待回测后确认 |
| 数据输入 | 用户级 LTV 日快照、用户归因变更表、现有消耗数据 |
| 判定方式 | 目标级点估计预测 ROI；选品闸门参数待回测 |
| 不涉及 | 后端 / API / 诊断服务代码、用户级消耗、模型训练、投放执行 |
| 与 ROI 链关系 | 并联；任一链达标即跟投；重复信号由冷却与下游幂等吸收 |
| 本期交付 | 需求文档、Dashboard / Decisions / Config 前端原型扩展、回测产品产出逻辑 |
三维度共用同一套聚合与判定逻辑，仅归因键不同：素材按 `material_id`，短剧按 `video_id`，campaign 按 `campaign_id`。
归因表是本链路的前置依赖。若某维度拿不到归因键，该维度不启用 LTV 链，不影响其余维度与现有 ROI 链。
阶段命名、阶段数量、是否需要观察期，全部待回测确定。本版判定结果只分「入选 / 未入选」两种，不定义具体阶段枚举。
## 3. 链路总览
```
LTV 用户日快照 ─────┐
归因变更表 ─────────┼─ 按 user_id + 生效日期关联 → 按 (维度, 目标) 聚合 → 前置校验
现有消耗数据 ───────┘（仅作分母）                                      ↓
                                                          点估计判定 → 入选 / 未入选
                                                                        ↓
                                                                入选 → FOLLOW_UP
```
- 「入选」产 `FOLLOW_UP`；「未入选」不产信号。
- 阶段定义待回测，原型不展示具体阶段名，只展示入选结果。
- 两条链共用现有信号契约与冷却机制，LTV 链不修改 ROI 链的阶段与阈值。
## 4. 数据契约
### 4.1 LTV 用户日快照
| 字段 | 类型 | 必填 | 语义 |
|---|---|---|---|
| date | date | 是 | 快照日期 |
| user_id | string | 是 | 用户稳定唯一键，与归因表同源 |
| predicted_ltv | number >= 0 | 是 | 截至 `horizon_days` 的预测累计收入，含 IAP + IAA |
| horizon_days | int | 是 | 预测周期，当前固定 90；后续扩展新周期靠此字段区分 |
| model_version | string | 是 | 模型版本，用于漂移排查与分版本回测 |
| currency | string | 是 | 币种，须与消耗数据一致 |
- 每个用户每天一行；同一用户取 `date` 最大的一条，不回填、不插值。
- 覆盖范围是「新归因用户」，含未付费用户；未付费用户预测值可为 0，但不能缺行。非归因用户不要求 LTV 行。
- 日更，T+1 凌晨 02:00 前到达；保留不少于 90 天历史，且支持按历史日期回溯。
- 回溯能力是回测的前置条件：回测必须用当日快照，不能拿最新预测回看历史。
### 4.2 用户归因变更表
| 字段 | 类型 | 必填 | 语义 |
|---|---|---|---|
| user_id | string | 是 | 与 LTV 表同键 |
| attribution_effective_date | date | 是 | 本次归因的生效日期 |
| attribution_time | datetime | 是 | 归因事件发生时间 |
| install_date | date | 是 | 安装日期 |
| campaign_id | string | 否 | 归因广告单元，未归因为空 |
| material_id | string | 否 | 归因素材 filename，未归因为空 |
| video_id | string | 否 | 归因短剧 / 视频 ID，未归因为空 |
| script_no | string | 否 | 剧本编号，信号透传 |
| shortplay_name | string | 否 | 短剧展示名，信号透传 |
| language | string | 否 | 语言代码，信号透传 |
| attribution_type | string | 是 | click / view / organic，明确归因规则 |
- 本表记录归因来源的**变更历史**，不是每日全量快照。同一用户可有多条记录，按 `attribution_effective_date` 区分。
- 回放规则：查询日期 D 时，取每个用户满足 `attribution_effective_date <= D` 的最新一条；无记录视为未归因。
- 必须是全量新增用户：自然量 / 未归因用户保留一条，目标键为空，`attribution_type=organic`。否则无法计算归因覆盖率。
- 同一 `user_id` + `attribution_effective_date` 唯一；同一行的每个维度键至多一个取值，多值冲突报数据错误。
- 三个归因键至少一个非空（organic 除外）；某维度键全空时，该维度 LTV 链不启用。
#### 4.2.1 归因来源与保护期
归因来源按**归因冷却期（保护期）**确认，不做永久锁定：
- 用户进入归因冷却期后，期内后续点击 / 曝光 / 重装不改变归因来源。
- 冷却期结束后，新触达按**末次归因**生成一条新记录，`attribution_effective_date` 为新归因生效日。
- 重装、多次触达按同一规则处理：期内锁定，期外按末次归因更新。
- 冷却期长度由上游归因规则确定，本需求不定义。
### 4.3 消耗数据
复用 PRD §6.3 的现有契约，不新增字段：
- 短剧日级、素材日级、campaign 小时级。
- **用户级没有消耗数据**；分母只能取目标维度的累计消耗，按现有消耗表汇总，不做用户级分摊。
- 是否限定消耗窗口（全部历史 / 近 90 天 / 与 LTV 周期对齐），列入回测对比项，最终口径待定。
### 4.4 前置校验（已确认）
前置校验回答「数据能不能信」，不决定目标好坏；决定目标好坏的选品闸门参数待回测。
| 校验项 | 规则 | 不满足处理 |
|---|---|---|
| 归因覆盖率 | 有任一归因键的新用户数 / 全部新用户数（按 `user_id` 去重）>= 90% | 该维度 LTV 链整体停用并告警 |
| LTV 覆盖率 | 有有效 `predicted_ltv` 的已归因用户 / 已归因用户 >= 90% | 该维度 LTV 链整体停用并告警 |
| 快照新鲜度 | 用户最新快照距今 <= 3 天 | 该用户按缺失处理，分子计 0 |
| 归因记录唯一性 | 同一 `user_id` + `attribution_effective_date` 唯一，每维度键至多一个值 | 整批拒绝，不做部分入表 |
| 分母 | 目标累计消耗 > 0 | 不判定 |
| 口径一致性 | 币种、时区、归因规则全表统一 | 整批拒绝 |
两个覆盖率的白话解释：
- 归因覆盖率：1000 个新用户里 800 个有归因键，覆盖率 80%。分子只算这 800 人的预测 LTV，分母却是目标全部消耗；覆盖率低，预测 ROI 会被系统性低估，因此低于 90% 直接停用该维度。
- LTV 覆盖率：这 800 个已归因用户里只有 720 个有有效 LTV，覆盖率 90%。缺的 80 人按 0 计入分子，同样低估 ROI；低于 90% 也停用该维度。
- 覆盖率为维度级全局口径，不按目标计算：无法知道未归因用户原本属于哪个目标，只能在维度层面判断数据是否可用。
## 5. 聚合与派生口径
### 5.1 聚合规则
| 项 | 规则 |
|---|---|
| LTV 取值 | 每个用户取 `date` 最大的快照 |
| 快照过期 | 最新快照距今 > 3 天视为缺失，分子计 0 |
| 缺失预测 | 分子计 0，不剔除分母 |
| 归因取值 | 判定日 D 取每个用户 `attribution_effective_date <= D` 的最新一条 |
| 目标分组 | 按 `campaign_id` / `material_id` / `video_id` 分别聚合，同一用户可同时进入三个维度 |
| 分母 | 目标维度累计消耗，按现有短剧 / 素材 / campaign 消耗表汇总 |
| 未归因用户 | 不进入任何目标；目标分母仍包含该目标全部消耗（含归因缺失部分），由归因覆盖率前置校验兜底 |
| 信息透传 | `language` / `script_no` / `shortplay_name` 取该目标下归因记录的一致值；冲突报数据错误 |
### 5.2 派生指标
| 指标 | 公式 | 说明 |
|---|---|---|
| 预测收入 | `Σ predicted_ltv` | 仅目标下已归因且有有效快照的用户 |
| 累计消耗 | `Σ spend` | 目标维度累计消耗 |
| 点估计预测 ROI | `预测收入 / 累计消耗`，消耗为 0 记 0 | 唯一判定指标 |
| 已归因用户数 | `count(distinct user_id)` | 目标下参与聚合的用户数 |
| 平均预测 LTV | `预测收入 / 已归因用户数` | 辅助解释，不参与判定 |
| 归因覆盖率 | 有归因键的新用户 / 全部新用户 | 维度级前置校验 |
| LTV 覆盖率 | 有有效预测的已归因用户 / 已归因用户 | 维度级前置校验 |
本版不使用重采样、分位数或风险调整口径。点估计的已知局限：结果对少数高 LTV 用户敏感，回测需检查长尾贡献；若回测发现结果不稳定，再评估截尾或分位数口径，不纳入本版默认方案。
## 6. 判定规则
### 6.1 判定机制（已定）
| 步骤 | 规则 |
|---|---|
| 1 前置校验 | 按 §4.4 执行；不通过则维度停用或该目标不判定 |
| 2 活跃闸门 | 目标近 N 日有消耗；否则未入选。防止停投目标靠存量用户长期入选 |
| 3 最小样本 | 目标已归因用户数 >= `n_min`；否则未入选，避免极少用户决定结果 |
| 4 点估计判定 | 点估计预测 ROI > θ 则入选，否则未入选 |
| 5 信号 | 入选产 `FOLLOW_UP`；未入选不产信号 |
N、`n_min`、θ 均为待回测参数，见 §6.2。判定不做重采样，不设置信度闸门。
### 6.2 待定参数与标定方法
本版不锁定任何闸门数值。前置表确认、数据到位后，先跑历史回测，再以回测报告冻结以下参数。
| 参数 | 符号 | 候选初始值 | 回测决定方式 |
|---|---|---|---|
| 盈利线阈值 | θ | 40% | 用 as-of 预测值与真实 D90 ROI 对齐，比较不同 θ 的精确率 / 覆盖率曲线 |
| 活跃窗口 | N | 7 天 | 分维度看停投资产占比与漏选率；campaign 与短剧可分别取值 |
| 最小样本 | `n_min` | 30 | 结合分桶精确率与极小样本目标的误选率确定 |
| 消耗窗口 | 无 | 全部历史累计 | 对比全部历史 / 近 90 天 / 与 LTV 周期对齐三种口径 |
| 最小累计消耗 | 无 | 暂不设 | 回测检查极小消耗目标是否被少数高 LTV 用户带入选；需要时再补 |
阶段命名、阶段数量、是否需要观察期，同样在回测后确定，本版不预设。
候选值只用于跑通回测，不作为上线结论。回测报告须给出每个参数的选择依据，并经评审后写入需求或配置。
## 7. 信号输出
| 字段 | 取值 |
|---|---|
| signal_type | `FOLLOW_UP` |
| target_dimension | product / material / campaign |
| target_id | video_id / 素材 filename / campaign_id |
| language_code | 归因表透传 |
| script_no | 归因表透传 |
| shortplay_name | 归因表透传 |
| reason | 固定前缀 `LTV选品通过`，后接点估计 ROI、已归因用户数、累计消耗、归因覆盖率（维度级）、LTV 覆盖率（维度级）、horizon、快照日、model_version |
| confidence | 本版固定 0.70 占位；语义为阶段判定置信度，不是概率，也不是回测精确率，待回测后按分桶精确率替换 |
| timestamp | 信号生成时间（UTC） |
- 冷却沿用 `(目标, FOLLOW_UP)`，默认 24 小时。
- 双链去重：推荐同一编排轮次内先跑 ROI 链、再跑 LTV 链并共用冷却状态；分进程运行时依赖下游按 `(维度, 目标, 类型)` 幂等。
- 信号不带 scale，放量规模由下游模板承载。
- 阶段命名待回测确定；本版对外只承诺「入选即产 `FOLLOW_UP`」。

## 9. 回测方案（产品产出）
### 9.1 回放口径
- 按历史日期逐日 as-of 回放：当日只用当日及以前的 LTV 快照、归因变更记录与消耗数据。
- 归因按 `attribution_effective_date <= 当日` 取最新一条；LTV 按当日快照取最新值。
- 禁止用最新模型预测回看历史；若无法按日回溯，回测不成立，需求不能进入上线评审。
- 三维度分别报告，不合并成一个数。
### 9.2 评估指标
| 指标 | 口径 |
|---|---|
| 精确率 | 入选目标中真实 D90 ROI > θ 的占比 |
| 覆盖率 | 入选目标数 / 当日有消耗且满足前置校验的目标数 |
| 增量 | 仅被 LTV 链选中、未被 ROI 链选中的目标数与表现 |
| 预测偏差 | 点估计 ROI 与真实 D90 ROI 的均值偏差，按维度与覆盖率分桶 |
| 长尾敏感性 | 头部 1% 高 LTV 用户对预测收入的贡献占比；对比截尾后的 ROI 变化 |
| 稳定性 | 相邻日期信号集合的 Jaccard 系数，识别抖动 |
### 9.3 回测产品产出逻辑
回测由产品侧组织，产出用于确定 LTV 选品的产品逻辑（参数、阶段、信号口径），不是开发任务清单。
| 产出 | 内容 |
|---|---|
| 分维度回测报告 | 素材 / 短剧 / campaign 分别给出精确率、覆盖率、预测偏差、稳定性 |
| 参数建议表 | θ、N、`n_min`、消耗窗口的取值建议、敏感度与选择依据 |
| 偏差与长尾分析 | 预测 vs 真实 D90 ROI；头部用户贡献；是否需要截尾或补最小消耗闸门 |
| 增量分析 | LTV 链相对 ROI 链的增量目标及表现 |
| 阶段建议 | 阶段命名、数量、是否需要观察期 |
| 上线建议 | 分维度进入 / 不进入结论与理由 |
| 原型 mock 数据 | 供 Decisions / Config 展示的示例信号与参数 |
### 9.4 验收建议线
以下为建议值，最终以回测报告评审结论为准。
| 项 | 建议标准 |
|---|---|
| 预测偏差 | 点估计 ROI 与真实 D90 ROI 均值偏差 <= ±10% |
| 精确率 | 入选目标真实 D90 ROI > θ 的精确率 >= 70% |
| 覆盖率 | >= 2%，且三维度分别达标 |
| 增量 | 存在仅由 LTV 链选中的有效目标 |
| 数据前置 | 归因覆盖率 >= 90%，LTV 覆盖率 >= 90%，快照与归因可按日回溯 |
| 无泄漏 | 回放全程不引用未来快照或未来归因记录 |
## 10. 风险与待定决策
| 风险 | 处理 |
|---|---|
| 归因表未定或维度不全 | 按维度分期启用；归因不可得的维度不上线 |
| 归因冷却期长度未定 | 作为归因规则输入参数；回测按实际规则回放 |
| 点估计对少数高 LTV 用户敏感 | 回测检查头部贡献与截尾敏感性；必要时再补风险调整口径 |
| 预测模型误差 | `model_version` 留痕；回测按版本分别报告 |
| 覆盖率不足导致 ROI 低估 | 归因覆盖率与 LTV 覆盖率双前置校验 |
| 选出来的都是已放量目标（自我强化 / 幸存者偏差） | 回测单列「近 N 日无消耗但历史预测好」的目标，评估增量 |
| 存量用户主导、信号响应慢 | 回测看新增用户贡献占比；必要时退回 cohort 口径 |
| 极小消耗目标被少数高 LTV 用户带入选 | 回测检查；需要时补最小累计消耗闸门 |
| 双链重复信号 | 共用冷却状态；下游幂等兜底 |
| 时区 / 币种 / 延迟不一致 | 契约写死；晚到整日跳过，不部分入表 |
待定决策：
1. 归因冷却期长度、归因变更历史与时效。
2. 阶段命名、阶段数量、是否需要观察期。
3. 闸门参数 θ、N、`n_min`、消耗窗口、是否补最小累计消耗。
4. 是否在后续版本引入截尾或分位数等风险调整口径。
5. 验收线最终取值。
6. 三维度上线顺序与是否分期。
7. 是否以及何时接后端、暴露判定 API。
## 11. 验收标准
| 项 | 标准 |
|---|---|
| 数据契约 | §4 三张输入表字段、粒度、覆盖率与回溯要求明确 |
| 前置校验 | §4.4 六项校验可执行，不通过有明确停用或拒绝行为 |
| 聚合口径 | 最新快照、过期 / 缺失处理、归因按生效日期回放、三维度分组规则确定 |
| 判定机制 | 点估计流程确定；重采样与分位数不在本版范围 |
| 闸门状态 | 本版不锁定数值；回测完成前不得上线 |
| 阶段状态 | 本版不定义阶段枚举；入选即产 `FOLLOW_UP` |
| 信号契约 | 复用 `BuildSignal`，只产 `FOLLOW_UP`，confidence 为占位值并标注非概率 |
| 原型 | Dashboard 增加 LTV 概览卡片与三维度入选分布；Decisions 增加链路来源筛选与 LTV 指标；Config 增加 LTV 参数占位与待回测提示 |
| 回测 | 按 as-of 回放，三维度分别报告，产品产出齐全 |
| 回归 | 现有 ROI 链、诊断服务、前端原有原型功能均不受影响 |
